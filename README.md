## 1. О проекте

Платформа для дистанционного обучения по видеокурсам. Пользователь регистрируется, выбирает курс в каталоге, записывается на него и проходит обучение по уровням: смотрит уроки, сдаёт тест в конце уровня и только после сдачи получает доступ к следующему уровню. После последнего уровня курс считается пройденным и выдаётся сертификат. Администратор управляет курсами, уроками, тестами и пользователями через свою панель.

Стек: Python, Django, SQLite, HTML/CSS/JS.

## 6. Как запустить проект (первый раз)

Нужны: Git, Python 3, VS Code (расширение Python).

1. Скачать проект. В VS Code: `Ctrl+Shift+P` → `Git: Clone` → вставить
   `https://github.com/ahmatovann/course-platform-kstu.git` → выбрать папку → **Open**.
2. Указать своё имя и почту для коммитов (один раз на ноутбуке):
   ```powershell
   git config --global user.name "ваш-ник-на-GitHub"
   git config --global user.email "почта-от-GitHub"
   ```
3. Открыть терминал (**Terminal → New Terminal**) и выполнить:
   ```powershell
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   python manage.py migrate
   python manage.py runserver
   ```
   Если `activate` выдаёт ошибку про скрипты — один раз выполнить
   `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` и повторить.
4. Открыть в браузере **http://127.0.0.1:8000**. Остановить сервер — `Ctrl+C`.

Каждый следующий раз: открыть папку в VS Code → `.venv\Scripts\activate` → `python manage.py runserver`.

## 7. Как работать над задачей

Одна задача = одна ветка = один pull request, который проверяет напарница.

1. На доске перетащить свою задачу в «В работе».
2. Перейти в ветку задачи и подтянуть свежий `main`:
   ```powershell
   git checkout main
   git pull
   git checkout feature/имя-ветки
   git merge main
   ```
3. Писать код и сохранять маленькими шагами — с номером задачи в сообщении:
   ```powershell
   git add .
   git commit -m "Добавила форму входа #2"
   git push
   ```
4. Когда задача готова — на GitHub открыть **pull request** в `main`. В описании: что сделано, как проверить, строка `Closes #номер`. В **Reviewers** выбрать напарницу. Задачу на доске — в «На проверке».
5. Напарница: **Files changed** → комментарий → **Review changes** → **Approve**.
6. После одобрения — **Merge pull request**. Задача закроется сама, веха покажет процент.

Код пишем только в файлах (окно редактора), в терминале — только команды `git`, `python`, `pip`.

## 10. Как объяснять код на паре

Любая страница в Django работает по одной цепочке — её и показываем в VS Code:

1. **Адрес** в браузере, например `/courses/`.
2. **`urls.py`** — какая функция отвечает на этот адрес.
3. **`views.py`** — что функция делает: берёт данные из базы, проверяет, сохраняет.
4. **`models.py`** — из какой таблицы данные.
5. **Шаблон `.html`** — как данные показаны на странице.

Над каждой функцией в `views.py` пишем комментарий с кодом ТЗ, например `# Ф-4. Каталог курсов`. Тогда нужное место находится поиском `Ctrl+Shift+F` по «Ф-4».
